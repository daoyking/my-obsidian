# 可观测性（Observability）

> 能看到 Agent 每次运行的「内部过程」——调了哪些工具、传了什么参数、模型输出什么、各阶段耗时、token 用量。是 [[W5-每日任务卡]] 的核心主题之一，也是排查与建立信任的前提。

## 为什么 Agent 特别需要它

- Agent 是**黑盒 + 非确定性**：同样的输入可能走不同工具路径、给出不同答案。
- 出问题难复现：用户说「它乱答了」，你得能回放那一次运行的完整链路才能定位。

## 核心模型：Span

- **span** = 一个「有开始 / 结束 / 耗时、可嵌套」的片段；一次运行 = 一棵 span 树。
- 例：`agent:run → retrieve / tool:calculator / model:generate`，每个 span 可附带事件（如 `tool-call`、token 数）。
- 本课 `w5-agent-eval` 的 `Tracer` 就是零依赖的迷你实现：离线即可跑，结构可直接对接 OpenTelemetry。

## 生产方案

- **OpenTelemetry（标准）**：span 标准、SDK 成熟，由 OTLP 导出到后端。
- **后端选型**：Langfuse（开源、对 LLM 友好）、LangSmith、Jaeger、Phoenix（本地调试）。
- **AI SDK 原生**：`streamText` / `generateText` 的 `telemetry: { isEnabled: true, functionId }` 走 OTel；**没有 OTel SDK 时自动 no-op，不会报错**（v7 不支持 `metadata` 字段）。
- **Mastra**：框架自带 playground / 追踪，开箱即用。

## 与评测的关系

- 评测（[[Agent评估]]）回答「结果好不好」，可观测回答「过程对不对」。
- 两者配合：评测掉分时，用 trace 回放定位是「工具调错」还是「模型答偏」。
