# 开放权重（Open Weights）

## 定义

「开放权重」（Open Weights）指模型发布者仅公开训练后的神经网络权重（及推理代码），但**不公开**原始训练数据、预处理方法、训练算法 / 超参。与之相对，真正的「开源」（Open Source）公开完整源代码，允许查看、修改、分支。

## 为什么重要

- 当前大量号称"开源"的模型实为"开放权重"，二者在透明度与可定制性上有根本差异（Gary Marcus，2026-08-11）
- 影响开发者选型：开放权重无法自由修改或深入调查，难以审计行为
- 影响监管者评估：权重开放 ≠ 可审计；训练数据 / 算法的不可见带来合规盲区
- 直接关联本库 [[Muse-Glimmer]]：Meta 以 Apache 2.0 发布的 30B 多模态模型即"开放权重"实例

## 开放权重 vs 真开源

| 维度 | 开放权重（Open Weights） | 真开源（Open Source） |
|---|---|---|
| 公开内容 | 训练后权重 + 推理代码 | 完整源代码 |
| 训练数据 | 不公开 | （软件无需训练数据，类比不适用） |
| 预处理 / 训练算法 | 不公开 | 公开 |
| 修改 / 分支 | 受限（仅权重层面） | 自由 |
| 可审计性 | 低（无法调查训练过程） | 高 |
| 许可证 | 常宽松（如 Apache 2.0） | OSI 认证许可证 |

**关键辨析**：Apache 2.0 等宽松许可证在"权重使用"层面宽松，但在"可理解性 / 可审计性"上仍受限——许可证宽松 ≠ 工程透明。

## 开放权重生态的扩展（2026-08-12）

来自 [[raw/articles/ai-hot-2026-08-12]]，本日新增多个开放权重实例，进一步丰富了"开放权重 vs 真开源"的对照谱系：

- **[[Nemotron]] 3.5 Lightning**（NVIDIA）：30B MoE 开放权重，BF16 + NVFP4 权重，面向本地智能体——典型开放权重
- **[[Ling]]-3.0-tiny**（蚂蚁百灵）：7.9B 总 / 1.3B 激活，BF16/FP8/INT4 三档——轻量级开放权重
- **关键动向**：Gary Marcus 透露英伟达将发布**真正开源（非仅开放权重）**的 Nemotron 新版本。若属实，这是从"开放权重"向"真开源"的罕见跨越，可能重新定义开源 AI 的边界，并削弱合作伙伴 OpenAI/Anthropic 的地位

**谱系观察**：当前开放权重模型已形成"激活参数梯度"——从 [[Muse-Glimmer]]（30B 全量）到 [[Nemotron]] 3.5（3B 激活）到 [[Ling]]-3.0-tiny（1.3B 激活），覆盖从消费级到边缘设备的部署谱。但"开放权重"标签下的透明度并未同步提升，监管与选型仍需警惕。
