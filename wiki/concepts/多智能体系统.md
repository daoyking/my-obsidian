# 多智能体系统（Multi-Agent Systems）

## 定义

由多个 AI 智能体在共享环境（代码库 / 市场 / 社会系统）中交互协作或竞争，完成任务或涌现新行为的系统。随着智能体在生产与社会系统中承担更多任务，智能体间交互量预计将超过人机交互量。

## 为什么重要

- 智能体间交互的复杂性远超单 Agent——涌现行为、协调机制、专业化分工都是新维度
- 单 Agent 风险模型无法预测多 Agent 系统的失败模式（如 OpenAI 智能体自建聊天室事件，见 [[Agent安全]]）
- 多智能体协作可能在效率上远超独立并行，但同时也可能放大个体层面的良性行为怪癖为系统性失败

## 核心机制

### 协调 vs 独立并行（Anthropic 2026-08-14 研究）

来自 [[raw/articles/ai-hot-2026-08-14]]（Anthropic Research）：

实验对比两种多智能体工作模式在漏洞发现任务上的表现：

| 模式 | 智能体数 | Token 消耗 | 发现漏洞数 | 重叠漏洞 |
|---|---|---|---|---|
| **协调（coordinated）** | 45 | 2700 万 | 266 | 12（与独立并行重叠） |
| **独立并行（parallel）** | — | 650 万 | 21 | 12（与协调重叠） |

**关键发现**：
- 协调模式发现漏洞数是独立并行的 **12.7 倍**，但 token 消耗是 **4.15 倍**——单位 token 效率仍优于独立并行
- 两种模式发现的漏洞仅 12 个重叠，**互补性极强**——意味着两种方法应组合使用而非替代
- 协调智能体**学会专业化分工**——涌现出的角色分化（非预设）

**警示**：个体层面的良性行为怪癖可能叠加为意外的系统性失败——这是多智能体系统独有的风险维度。

## 示例

```
[协调模式]
  45 agents ↔ 共享上下文 ↔ 协调机制 → 266 漏洞（专业化分工涌现）

[独立并行]
  N agents ‖ 独立运行 → 21 漏洞（无协调，纯并行）

[组合]
  协调 + 独立并行 → 266 + (21 - 12) = 275 漏洞（互补）
```

## 落地形态：18 个 Agent Team 样例（2026-09-01）

来自 [[raw/articles/awesome-llm-apps]]：`agent_teams`（13 个）+ `multi_agent_apps`（5 个）+ `trust_gated_agent_team`。这些样例把上面的研究结论落成了可跑的代码，并暴露出一个共性——**团队 = 角色分工 + 编排模式**：

| 编排模式 | 代表项目 | 特点 |
|---|---|---|
| 流水线分工 | AI Recruitment（筛选→排期）、AI Legal（研究→合同→策略） | 顺序传递，职责单一 |
| 专家会审 | Multimodal Design Agent Team、AI VC Due Diligence | 多专家并行评价同一对象 |
| 路由 + 回退 | AG2 Adaptive Research Team | 按任务路由到合适 agent，失败回退 |
| 自治演进 | AI Self-Evolving Agent（EvoAgentX） | agent 重写自己的工作流，呼应 [[Agent持续进化]] |
| **信任门禁** | Trust-Gated Multi-Agent Research Team | 每个 agent 验证身份，每个动作进**哈希链审计日志** |

最后一项直接回应上面「个体良性怪癖叠加为系统性失败」的风险：**可审计性是多智能体协作的前提**。哈希链让每次 agent 动作不可篡改、可追溯——这与 [[Agent安全]] 的治理思路一致，值得单独研究其实现。

另外 `agent_skills/advisor-orchestrator-worker` 给出了一个「顾问-编排-执行」三元结构（Claude Fable 5 顾问 / GPT-5.6 编排 / Gemini 3.7 Flash 执行），是**异构模型分工**的实例：不同能力档位的模型承担不同角色，而非全部用最强模型。
