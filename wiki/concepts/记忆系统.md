# 记忆系统（Agent Memory）

## 定义

让 Agent 跨会话保留与调用信息的能力体系。把上下文管理从「当前对话」延伸到「持久化知识」，让 Agent 不仅记住当下，还能积累经验。

## 为什么重要

- 单靠上下文窗口有限且会丢失——记忆系统让 Agent 长期可用
- 是 [[上下文工程]] 的跨会话延伸
- 本知识库本身就是一个外部记忆系统（raw + wiki）

## 三层次评估框架

来自 [[raw/papers/ai-agents-in-depth]] 第 3 章：
1. **短时/工作记忆**：当前上下文窗口内
2. **长时记忆**：跨会话持久化（向量库、知识库）
3. **跨会话策略记忆**：Agent 自身行为模式的沉淀

## 认知类型（借自认知科学）

- **情景记忆**：具体事件经历（某次对话/任务）
- **语义记忆**：事实知识（概念、定义）
- **程序记忆**：如何做事（SOP、Skill、工具用法）

## 四种存储格式

书中详述四种用户记忆存储格式（文本/结构化/可执行代码/参数化），从简单到高级演进。

## 记忆剂量校准：按模型能力匹配注入策略（2026-08-19）

来自 [[raw/articles/ai-hot-2026-08-19]]（IBM Research，Hugging Face Blog）：

**核心发现**：智能体记忆并非可随意开启的功能，而是需按模型能力**校准剂量**的变量。

- **强模型**（DeepSeek-V3.2，671B MoE）：适合注入完整指南集，任务完成率提升 **+9.5 个百分点**
- **较弱模型**（gpt-oss-120b，117B MoE）：采用精选检索效果最佳，提升 **+16.1pp** 且仅增加 **+5% token**
- **方法**：从智能体过往轨迹中蒸馏指南并在推理时注入，无需更新权重或人工标注
- **启示**："越多越好"是错误假设——记忆注入的收益是模型能力的函数

**定位**：这直接挑战了 Agent 工程中的常见直觉（"加记忆总是更好"），为 [[记忆系统]] 的工程设计提供了校准原则：
1. 记忆注入策略应与模型能力匹配（强模型用全量，弱模型用精选检索）
2. 记忆 ROI 需量化评估（token 成本 vs 任务完成率提升）
3. 本库的 `CLAUDE.md` + wiki 体系本质上是一种"轻量级语义记忆"，对中小型模型（如 Qwen3.8-27B）的价值可能需要重新评估

**对本库的启示**：本库 Ingest 流程中，每日压缩 20+ 条 AI HOT 日报为 `AI资讯.md` 的表格汇总，本质上是在做"精选检索"而非"全量注入"——这与 IBM 研究的结论一致：对非最强模型，精简记忆优于全量记忆。

## 与本知识库的映射

- 本库的 `wiki/concepts`（语义记忆）、`projects`（情景记忆）、`templates`/Skill（程序记忆）正好对应认知三类型
- 卡帕西 LLM Wiki 方法本质就是「把 Agent 的语义记忆外置成可编辑 Markdown」

## 实现阶梯：6 个可运行样例（2026-09-01）

来自 [[raw/articles/awesome-llm-apps]] 的 `llm_apps_with_memory_tutorials`，正好从易到难覆盖上面四种认知类型：

| 项目 | 记忆层次 | 对应认知类型 |
|---|---|---|
| Llama3 Stateful Chat | 会话内持久化 | 短时/工作记忆 |
| LLM App with Personalized Memory | 跨对话保持上下文 | 情景记忆 |
| AI Travel Agent with Memory | 记住用户偏好 | 语义记忆（偏好事实） |
| AI ArXiv Agent with Memory | 记住研究兴趣 | 语义记忆 |
| Local ChatGPT Clone with Memory | 每用户一份个人记忆，全本地 | 长时记忆 + 隐私隔离 |
| Multi-LLM Application with Shared Memory | 不同模型共享一份记忆 | **跨模型记忆可移植** |

最后一项最值得关注：**记忆与模型解耦**——同一份记忆服务于不同 LLM，意味着记忆层是独立基础设施而非某个模型的附属品。这与本库的做法一致：wiki 是 Markdown 文件，换任何模型都能读。
