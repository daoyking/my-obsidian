# 机器遗忘（Machine Unlearning）

## 定义

机器遗忘研究如何让已训练的模型"遗忘"特定训练数据的影响——即在不重新从头训练的前提下，移除某条/某批数据对模型权重的贡献。是数据隐私（如 GDPR 被遗忘权）、模型纠错（如删除投毒数据）、合规治理的关键技术。

## 为什么重要

- **隐私合规**：用户行使"被遗忘权"时，企业需证明数据已从模型中移除
- **模型纠错**：训练数据被投毒或标注错误时，需低成本移除错误影响
- **降低重训成本**：从头重训成本极高，机器遗忘提供"局部手术"方案
- 与 [[Agent安全]] 相关：被投毒的 Agent 可通过遗忘机制移除恶意数据影响（见 OpenAI 智能体被投毒数据攻破事件，[[raw/articles/ai-hot-2026-08-08]]）

## 核心机制

### 传统做法

对所有待遗忘数据点一视同仁——逐一计算其影响力并移除，计算成本与遗忘集大小线性相关。

### Apple 低影响力数据点优化（2026-08-14）

来自 [[raw/articles/ai-hot-2026-08-14]]（Apple Machine Learning Research）：

- **核心洞察**：训练数据中存在"低影响力数据点"——对模型输出影响可忽略的点
- **优化策略**：对低影响力点无需逐一移除，可批量跳过，大幅降低计算成本
- **方法**：通过影响力函数（influence function）对比语言与视觉任务，识别出对模型输出影响极小的数据子集
- **挑战**：该方法挑战了现有遗忘技术"对所有遗忘集数据点一视同仁"的默认假设

## 示例

```
[传统遗忘]
  遗忘集 D_forget = {d1, d2, ..., dn}
  for each d in D_forget:
    计算影响力 → 移除  # 成本 O(n)

[Apple 优化]
  遗忘集 D_forget = {d1, d2, ..., dn}
  分类：
    - 高影响力点 → 逐一移除  # 成本 O(k), k << n
    - 低影响力点 → 批量跳过  # 成本 O(1)
```

## 待研究问题

- "低影响力"的判定阈值如何设定？过低会漏掉真正有影响的数据，过高会过度移除
- 低影响力点是否在对抗场景下被利用——攻击者是否会把投毒数据伪装成低影响力点？
- 影响力函数在高维大模型（如 2.4T MoE）上的计算成本是否可承受？
- 机器遗忘与 [[知识编辑]] 的关系——前者移除数据影响，后者直接编辑模型知识，两者是否可统一？
