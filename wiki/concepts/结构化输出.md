# 结构化输出

## 定义

让模型按**预定 schema** 而非自由文本输出，通常以 JSON 形式，可被程序直接解析。常见实现：JSON Mode、function calling 的 parameters、constrained decoding / grammar-based sampling（如 JSON Schema → 状态机约束 token）。

## 为什么它是生成式 UI 的地基

[[生成式UI]] 的每一层都建立在「模型输出可被解析」之上：

- L1 工具渲染卡片 → 工具参数是结构化输出
- L2 共享状态 → 状态字段与 JSON Patch 是结构化输出
- L3 [[A2UI]] 声明式组件树 → 整棵组件树就是一份结构化输出
- L4/L5 生成应用 → 生成的代码是最难校验的一类结构化输出

**模型输出稳定性直接等于 UI 稳定性**：一次非法 JSON，整个界面崩。因此 schema 校验 + 降级渲染是必选项，不是加分项（Vue 侧降级实现见 [[生成式UI渲染协议]]）。

## 三种强度

| 强度 | 手段 | 可靠性 | 代价 |
|---|---|---|---|
| 弱 | 提示词里写「只返回 JSON」 | 低，模型可能包裹解释或 markdown 代码块 | 零成本，任何模型可用 |
| 中 | JSON Mode / function calling | 中高，语法有保证 | 需模型支持 |
| 强 | Constrained decoding（grammar 约束每个 token） | 最高，语法层不可能错 | 需推理框架支持，可能损质量 |

`ai-knowledge-explorer` 样例恰好是「弱」强度的典型：它靠提示词让 gpt-4o 返回原始 JSON 再解析，README 明确提醒——**换模型后必须重新验证「只返回 JSON」这条指令是否还被遵守**，因为有些模型即使被告知不要，仍会包裹解释文字。

## 校验与降级

1. **Schema 校验**：Zod / JSON Schema，失败即降级
2. **重试**：把错误信息回喂模型让它改正（自校正循环）
3. **降级渲染**：未知或非法结构渲染成可折叠的 JSON 卡片 + 重试按钮，而不是让页面白屏
4. **部分渲染**：流式场景下，允许渲染已解析成功的子树

## 我的观点

- 结构化输出是 [[上下文工程]] 与前端的分界线：**schema 既是给程序看的接口，也是给模型看的 prompt**。写 `description` 时必须当成在写提示词。
- 前端工程师在这里有天然优势：我们长期与「不可信输入」打交道（表单校验、接口容错），这套肌肉记忆可以直接迁移到模型输出上。
