# W2 每日任务卡 · 流式聊天 + 工具调用

> 配套 [[Agent开发学习计划]] 的 W2 周执行卡。主题：用 [[Vercel AI SDK]] 搭一个流式聊天界面，并让模型能主动调用工具（时间 / 计算 / 天气），前端把工具调用过程实时可视化。
> 已落地的可运行脚手架：`learning-AI/w2-agent-chat`（Express 后端 + Vite/React 前端），可直接 `npm install && npm run dev` 参考。

## 周目标（验收总纲）

- [ ] 本地能跑一个网页聊天机器人，回复**逐字流式**出现
- [ ] 模型能**主动调用 ≥3 个工具**（时间 / 计算 / 天气），且前端**可视化**每次调用的「输入 / 输出 / 状态」
- [ ] 代码 push 到 GitHub，附一句话说明

预计总耗时：10h（约 5 天 × 2h）

---

## 🗓️ D1 · 概念 + 最小脚手架

**目标**：搞懂 Agent 循环（思考→行动→观察），跑通一个能收发消息的空壳聊天页。

**任务**
1. 读 [[Vercel AI SDK]] 的 `useChat` / `streamText` 两个 API 的官方示例，口述「消息如何流回前端」。
2. 初始化工程：`Vite + React + TypeScript` 前端，`Express + Node` 后端（或直接沿用 `learning-AI/w2-agent-chat`）。
3. 后端先写一个**不带模型**的回声接口：`POST /api/chat` 原样返回用户输入，验证前后端联通。

**验收标准**
- 打开 http://localhost:5173 能看到输入框，发消息后气泡回显。
- 能说清「SSE / 流式」与普通 JSON 接口的区别。

**产出**：可运行的空壳聊天页（GitHub 提交 1 次）。
**耗时**：2h

---

## 🗓️ D2 · 接真实模型 + 流式输出

**目标**：把回声接口换成 `streamText`，确认回复逐字出现。

**任务**
1. 后端引入 `@ai-sdk/openai`，用 `createOpenAI({ baseURL })` + `.chat(model)` 走 Chat Completions（兼容 DeepSeek / 通义）。
2. 用 `streamText({ model, messages: await convertToModelMessages(messages) })` 生成，调 `result.pipeUIMessageStreamToResponse(res)` 把流灌给前端。
3. 前端 `useChat({ api: '/api/chat' })` 消费流，`messages[].parts` 里 `type:'text'` 逐字渲染。

**验收标准**
- 输入「你好」，回复**逐字**出现而非整段弹出。
- `.env` 里配好 key 后能真实对话（DeepSeek 推荐）。

**产出**：真实可对话的流式聊天页。
**耗时**：2h

---

## 🗓️ D3 · 工具调用（Agent 核心）

**目标**：让模型在合适时调用工具，理解 `tool_calls` 循环。

**任务**
1. 用 `tool({ description, inputSchema, execute })`（v7 注意是 `inputSchema` 不是 `parameters`）定义 3 个工具：`getCurrentTime` / `calculator` / `getWeather`。
2. 把 `tools` 传给 `streamText`，**不要**自己写循环——SDK 自动处理「模型要调工具 → 本地执行 → 结果回灌 → 再问」。
3. 问「现在几点了？」「12*(3+4) 等于几？」验证模型会先调工具再回答。

**验收标准**
- 问时间类问题，模型返回的结果来自 `getCurrentTime` 而非凭空编。
- 能口述「工具调用的那一轮多了一轮模型↔工具的往返」。

**产出**：带工具调用的 Agent（≥3 工具）。
**耗时**：2.5h

---

## 🗓️ D4 · 工具调用可视化（前端护城河）

**目标**：把工具调用做成时间线卡片——这正是前端工程师做 Agent 的差异化。

**任务**
1. 前端遍历 `message.parts`，遇到 `type` 以 `tool-` 开头的片段，渲染一个 `ToolCall` 卡片。
2. 卡片展示：工具名、`input`（JSON）、`output`（JSON）、运行中 / 完成状态。
3. 打磨样式（暗色主题、状态色），让「模型思考 → 调工具 → 出结果」一眼可见。

**验收标准**
- 聊天流里能看到工具调用卡片，含输入/输出。
- 工具执行中显示「运行中…」，完成显示「完成」。

**产出**：带工具时间线的聊天 UI（截图进作品集）。
**耗时**：2h

---

## 🗓️ D5 · 复盘 + 扩展 + 入库

**目标**：巩固理解，加一个自己的工具，沉淀到 GitHub。

**任务**
1. 自己**新增 1 个工具**（如查本地文件、接真实天气 API、查数据库），体会「描述决定模型何时调」。
2. 写一段复盘（≤200 字）：「这个 Agent 的循环是怎么跑起来的？前端在哪一环创造价值？」
3. `git push` 到 GitHub，README 写清运行步骤。

**验收标准**
- [ ] ≥1 个自写工具可用
- [ ] GitHub 有提交 + README
- [ ] 能向别人讲清楚 Agent 循环

**产出**：W2 作品（GitHub 链接 + 复盘）。
**耗时**：1.5h
