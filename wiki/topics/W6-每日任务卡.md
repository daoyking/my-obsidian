# W6 每日任务卡 · 作品集交付

> 配套 [[Agent开发学习计划]] 的 **W6（作品集交付）** 主题执行卡。
> 主题：把 **W2 流式聊天 / W3 RAG / W4 多步编排 / W5 评测可观测** 整合为一个统一、可演示、可投递的**作品集**，
> 配套录屏脚本与面试讲解要点。目标不是再写一个新模型，而是把前 5 周的积累「打包成能打动招聘方的东西」。
> 已落地的交付物：`learning-AI/w6-portfolio/`（自包含作品集站点 `index.html` + 说明 README），引用同级四个真实工程为「作品」。

## 周目标（验收总纲）

- [ ] 产出 1 个**打磨过的作品集**：统一呈现 4 个工程 + 2 套质量护栏（Eval / Observability），且可本地一键预览
- [ ] 四个工程都能**一键跑通**（`npm install && npm run dev/start`），并写清演示看点
- [ ] 准备一段 **3–5 分钟录屏脚本** + **面试讲解要点**，能讲清「前端差异化 + 工程化护栏」
- [ ] 把评测（W5 `runEval`）与可观测（W5 `Tracer` / `telemetry`）**嫁接到作品集叙事**，让作品集不止是「能跑」
- [ ] 交付到 GitHub + 知识库（本卡 + 计划主页 W6 状态更新）

预计总耗时：15h（约 5 天 × 3h）

> 避坑（W6 / 投递向）：作品集站点要**零依赖、可离线打开**——别用需要构建/CDN 的框架，面试官本地双击就能看；项目链接用相对路径（如 `../w4-resume-scorer/README.md`）串起故事线；录屏前务必把每个工程的 `.env` 配好并先 `npm run` 自测一遍，避免录到「key 缺失 / 端口被占」；讲解时把 W5 的 eval/observability 当「加分项」点出来，这是区分「玩具练手」与「工程化交付」的关键；相对链接在本地 `file://` 下可用，但若部署到 GitHub Pages 需确认路径（根目录部署用 `/learning-AI/...` 或改成绝对路径）。

---

## 🗓️ D1 · 作品集定位 + 结构

**目标**：想清楚「我要交付什么」，确定整合结构，不盲目开写。

**任务**
1. 回看 [[Agent开发学习计划]] 路线图与 [[W2-每日任务卡]]/[[W3-每日任务卡]]/[[W4-每日任务卡]]/[[W5-每日任务卡]]，列出每个工程的「一句话价值 + 技术栈 + 演示看点」。
2. 定调：作品集本身 = W6 的「1 个打磨作品」；它引用 w2/w3/w4/w5 四个真实工程为「作品」，W5 的 eval/observability 作为「工程实践」差异化模块。
3. 画信息架构：导航（首页 / 路线 / 作品 / 工程实践 / 演示）→ 各 section 内容要点。

**验收标准**
- 能口述「作品集不是第 5 个模型，而是前 5 周积累的打包与放大」。
- 列出 4 个工程的「价值 + 技术栈 + 看点」三栏表。

**产出**：作品集信息架构（脑子里或草稿）。
**耗时**：2.5h

## 🗓️ D2 · 作品集站点搭建（前端可视化）

**目标**：用前端工程师的老本行，做一个美观、自包含、可演示的作品集页面。

**任务**
1. 写 `w6-portfolio/index.html`：单文件、内联 CSS/JS、**无外部依赖**，含 Hero（前端→AI Agent）、W1–W6 路线时间线、4 个作品卡、工程实践（Eval + Observability）、录屏脚本。
2. 做轻交互：滚动 reveal 动画、导航高亮（IntersectionObserver）、明/暗主题切换（localStorage）。
3. 作品卡链接用相对路径指向同级工程 `README.md`，把四个工程串成一条线。

**验收标准**
- 双击 `index.html` 即可在浏览器完整查看，无需联网、无需构建。
- 能讲清「前端的可视化 / 交互 / 体验能力，本身就是我做 AI 产品的护城河」。

**产出**：`w6-portfolio/index.html`（自包含作品集站点）。
**耗时**：3.5h

---

## 🗓️ D3 · 跑通四个工程 + 写录屏脚本

**目标**：确保每个「作品」都真实可演示，并准备好录屏脚本。

**任务**
1. 逐个自测：`w2-agent-chat`(`npm run dev`) / `w3-rag-qa`(`npm run dev`) / `w4-resume-scorer`(`npm start`) / `w5-agent-eval`(`npm test` + `npm run eval`)，确认 `.env` 配好、端口空闲。
2. 在 `w6-portfolio/README.md` 写清：每个工程运行命令 + 演示看点表 + 评测怎么跑 + 可观测怎么接。
3. 写 3–5 分钟录屏脚本（开场 20s → W2 50s → W3 50s → W4 50s → W5 60s → 收尾 30s），见 `index.html`「演示」节。

**验收标准**
- [ ] 四个工程本地都能跑起来、有可见输出
- [ ] README 有「运行 + 评测 + 可观测 + 录屏」四段，新人照做能复现

**产出**：自测通过 + `w6-portfolio/README.md`。
**耗时**：3.5h

---

## 🗓️ D4 · 评测 / 可观测嫁接到作品集叙事

**目标**：让作品集不止「能跑」，而是「有质量护栏」，把 W5 的差异化讲透。

**任务**
1. 在 `index.html`「工程实践」节讲清：Eval（确定性 vs LLM-as-judge、`runEval` 可注入、CI 回归）与 Observability（Span 模型、零依赖 Tracer、AI SDK `telemetry` → OTel/Langfuse）。
2. 在 README 写「把 W2–W4 各写一份评测数据集，CI 里跑 `runEval` 做回归门禁」「Tracer 接真实 Langfuse 录线上 trace」两个可选增强。
3. 准备面试讲解要点：前端护城河 / 工程化思维 / 框架取舍（裸 SDK vs Mastra）/ 迁移能力。

**验收标准**
- 能口述「评测解决『改了没变差』，可观测解决『线上怎么查』，二者是产品的分水岭」。
- 面试要点能脱稿讲 2 分钟。

**产出**：作品集叙事闭环 + 面试话术。
**耗时**：2.5h

## 🗓️ D5 · 收尾（GitHub + KB + 计划主页）

**目标**：把 W6 交付物沉淀到 GitHub 与知识库，关闭整条学习路线。

**任务**
1. `git push` 工程（含 `w6-portfolio/`）到 GitHub，`w6-portfolio/README.md` 写清预览方式（`python3 -m http.server` 或双击）。
2. 在知识库完成本卡（[[W6-每日任务卡]]），并与 [[Agent开发学习计划]]、W2–W5 任务卡、[[Agent评估]]、[[可观测性]] 互链。
3. 更新 [[Agent开发学习计划]]：把 W6 标为「进行中/完成」，补「作品集 = 整合交付」的验收说明。
4. 写 ≤150 字复盘：「从 W1 概念到 W6 交付，哪个环节最难？前端背景在哪一步最加分？下一步怎么补强（如真实 Langfuse / 上线一个小 Agent）？」

**验收标准**
- [ ] GitHub 有 `w6-portfolio/` 提交 + README
- [ ] KB 有 W6 任务卡，计划主页 W6 状态更新
- [ ] 能 30 秒讲完「6 周我做了什么、拿到了什么」

**产出**：W6 作品集（GitHub + 录屏脚本 + KB + 复盘）。
**耗时**：3h
