# W4 每日任务卡 · Mastra 多步编排 Agent

> 配套 [[Agent开发学习计划]] 的 **W4（编排与记忆）** 主题执行卡。
> 主题：用 [[Mastra]]（TS 原生 Agent 框架）搭一个「读简历 → 抓 JD → 多维度打分 → 给改进建议」的**多步编排 Agent**，体会它相对 W2 裸写 `streamText` 多出来的能力：Agent 封装、工具、结构化输出、**工作流编排**与（可扩展的）记忆。
> 已落地的可运行脚手架：`learning-AI/w4-resume-scorer`（独立项目，Node + `tsx`），可直接 `npm install && npm start` 参考。

## 周目标（验收总纲）

- [ ] 用 Mastra `Agent` 把「模型 + 工具 + 提示」打包成一个可复用单元，跑通「读简历→抓 JD→打分」
- [ ] 能用 Mastra `Workflow` 把流程拆成**显式有向步骤**（`loadData → score`），比 Agent 黑盒更可控
- [ ] 代码 push 到 GitHub，README 写清运行步骤，能讲清「Agent 编排」与「裸写循环」的差异

预计总耗时：12h（约 5 天 × 2.5h）

> 避坑（Mastra 1.57）：`Agent` 构造需 `id` 字段；`createTool` 在 `@mastra/core/tools`、`Agent` 在 `@mastra/core/agent`、`createStep/createWorkflow` 在 `@mastra/core/workflows`；`model` 用 `createOpenAI().chat(model)` 走 Chat Completions（兼容 DeepSeek/通义）；`createWorkflow({...}).then(s1).then(s2).commit()` 才建执行流；运行用 `workflow.createRun().start({ inputData })`（**不是** `.execute()`）。

---

## 🗓️ D1 · 框架认知 + 工程初始化

**目标**：搞懂「为什么需要 Agent 框架」，跑通 Mastra 最小骨架。

**任务**
1. 读 [[Mastra]] 主题，对比 W2 裸写 `streamText`：Mastra 把「模型 + 工具 + 提示」封装成 `Agent` 类，可复用、可测试、可观测。
2. 初始化工程：Node + TypeScript + `tsx`（可沿用 `learning-AI/w4-resume-scorer`）。
3. 装依赖 `@mastra/core @ai-sdk/openai zod dotenv`，写一个 `import { Agent } from '@mastra/core/agent'` 的最小脚本确认导入路径正确。

**验收标准**
- 能口述「Mastra 的 Agent = 模型 + 工具 + 指令的打包单元，相对裸写循环更像『可复用的组件』」。
- 子路径导入不报错（`Agent` 来自 `@mastra/core/agent`）。

**产出**：可运行的 Mastra 空工程（GitHub 提交 1 次）。
**耗时**：2h

---

## 🗓️ D2 · 工具（多步编排的第一步）

**目标**：用 Mastra `createTool` 把「读简历 / 抓 JD」做成 Agent 能主动调用的能力。

**任务**
1. 用 `createTool({ id, description, inputSchema, execute })` 定义 `readResume` / `readJobDescription`（从 `sample/` 读文本；`inputSchema` 用 `z.object({})` 表示无参）。
2. 注意 `id` 必填；`execute` 返回对象（如 `{ resume }`），Mastra 会把结果回灌给模型。
3. 单测直接调 `readResume.execute({})` 验证能读到 `sample/resume.txt` 内容。

**验收标准**
- 两个工具都能被独立调用并返回正确文本。
- 能口述「工具让 Agent 能主动读取外部数据，是『多步编排』的原子能力」。

**产出**：`readResume` / `readJobDescription` 两个工具。
**耗时**：2.5h

---

## 🗓️ D3 · Agent 封装（模型 + 工具 + 指令）

**目标**：把模型、工具、打分指令打包成 `Agent`，一键生成报告。

**任务**
1. 用 `new Agent({ id, name, instructions, model, tools })` 定义 `resumeScorer`；`instructions` 写明打分维度（技术栈匹配 / 工程能力 / AI 经验 / 作品集 / 表达）与输出格式（中文 Markdown + 总分 + 3 条建议）。
2. `model` 用 `createOpenAI({ baseURL, apiKey }).chat(model)`（走 Chat Completions，兼容 DeepSeek）。
3. 跑 `resumeScorer.generate('请评估这份简历与目标岗位')`，验证 Agent 会**先调 `readResume` 再调 `readJobDescription`**，最后给出结构化报告。

**验收标准**
- 一次 `generate` 触发「读简历→抓 JD→打分」的完整链路。
- 输出是带维度分数 + 总分 + 建议的 Markdown。
- 能对别人讲清「`Agent` 和 W2 的裸 `streamText` 差在哪」。

**产出**：可运行的 `resumeScorer` Agent。
**耗时**：2.5h

---

## 🗓️ D4 · Workflow 显式编排（进阶）

**目标**：把「读取→打分」拆成有向步骤，获得比 Agent 黑盒更强的可控与可观测。

**任务**
1. 用 `createStep({ id, inputSchema, outputSchema, execute })` 写两步：`loadData`（并行读简历+JD）与 `scoreStep`（调 `resumeScorer.generate`）。
2. 用 `createWorkflow({ id, inputSchema, outputSchema }).then(loadData).then(scoreStep).commit()` 建执行流。
3. 运行 `scoreWorkflow.createRun().start({ inputData: {} })`，读 `res.steps` 看每步输出，理解「显式编排」如何拆黑盒。

**验收标准**
- Workflow 能跑出与 Agent 版等价的报告。
- 能口述「Workflow 把流程变成可观测的有向图，便于加步骤 / 改顺序 / 复用」。

**产出**：`scoreWorkflow` 编排版（与 Agent 版对照）。
**耗时**：2.5h

---

## 🗓️ D5 · 复盘 + 扩展 + 入库

**目标**：巩固「编排」心智，加一个增强点，沉淀到 GitHub。

**任务**
1. 自己**加 1 个增强**（任选）：给 Agent 接 `Memory` 记住历史简历做「前后对比」；或把 `scoreStep` 拆成「打分 + 润色」两步；或加第三个工具（如抓在线 JD URL）。
2. 写一段复盘（≤200 字）：「Mastra 的 Agent / Workflow 分别解决什么问题？何时用 Agent、何时用 Workflow？」
3. `git push` 到 GitHub，README 写清「填 key → install → start」步骤，并注明 Workflow 进阶用法。

**验收标准**
- [ ] ≥1 个自加增强可用
- [ ] GitHub 有提交 + README
- [ ] 能讲清 Agent 与 Workflow 的取舍

**产出**：W4 作品（GitHub 链接 + 复盘）。
**耗时**：2.5h
